## 主動執行與漏做防線（使用者要求後新增）

- 已授權範圍內發現阻擋、故障或未完成的必要後續，當回合就登記工作並實際啟動查核／修復，不只告知、不等觀察員再次催促。不以這條規則推論實盤或其他帳戶授權。
- 背景任務先登記 lab/shared/work_status.json，填真實目前步驟、下一步及證據，再派工。每個檢查點更新，失敗、受阻、取消與等待父代理驗收都要明示。
- 每次報告前檢查引擎 blockers 與未完成工程任務。每個已知問題必須有正在執行的工作，或明確的受阻原因／尚未執行狀態。沒有工具執行證據，不能說已著手。
- 子代理完成後由父代理接手驗收與部署，不能把交付摘要當成完工。完成須讀回實際目標與狀態，才在看板標 completed。
- 自動恢復不等於根因修復。保留診斷任務，直到證據支持修復或有理由判定不需改動。不得用更新時間、虛構heartbeat或舊測試掩蓋停滯。
- 無法執行、權限限制或真正需要使用者提供資料時，當回合直接標 blocked 並說清楚。助手並非隨時自主喚醒，沒有常駐程序或排程支撐的工作不能承諾持續監控。

## PAPER 是實盤工程預備，不是一次性模擬（使用者新增要求）

- 最終目標是讓 PAPER 成熟後能低摩擦切換至實盤。現在就處理系統及工程缺陷，不以「只是紙盤」降低可靠性與驗收標準。
- 策略、行情、風控、訂單生命週期、帳務、稽核、健康監控與運維採可共用的契約，模擬成交與真實交易所 execution adapter 隔離。切換目標是不重寫交易核心，而非將未驗證的私人 API 接線當成完工。
- PAPER 階段預先測試時間同步／資料時效、重啟恢復、持久狀態、斷線／重連、拒單、部分成交、撤單競態、重複事件、下單結果不明與防重單、資產／持倉／訂單／費用對帳、風控停止與故障告警。尚未实现或验收者明示未完成，不用模擬測試宣稱實盤已驗收。
- 正式實盤啟用前，仍須另驗交易權限與憑證隔離、交易所 execution adapter／私人事件、實際對帳及明確啟用條件。此工程方向不授權現在送真單、讀取憑證、改動其他帳戶，亦不代表策略已有獲利證據。

## 自主交易與外部工程分工（最新使用者要求）

- 助手是自主交易決策者，不是 coding labor。策略、風險、研究方向、實驗及系統需要什麼由助手決定，不委派交易判斷。
- 所有 coding、testing、code review、debug 交外部 coding agent，透過 GitHub Issues，由使用者人工轉交。助手只觀察足以描述問題的證據，定義成果、限制、不變條件及驗收，不指定逐檔實作或自行修碼。
- Issue 標籤為 BUG／ENGINEERING／RESEARCH INFRASTRUCTURE／OBSERVABILITY，內容按可能公開處理，不含個資、帳戶細節、本機絕對路徑、聊天識別或憑證。
- 每個 Issue 明示：repo 是 local 單向鏡像。外部 agent 只在非 main 分支工作並開 PR，不得 push 或 merge main。agent 負責品質、測試及短 PR 摘要（改動、測試、範圍外觸及）。
- 助手不 review code。只確認精確 PR head 的 GitHub CI 綠燈與成果驗收，再套用 local 工作目錄，由正常 sync 發布，追加 versions.md。既有已實作且已驗證候選依使用者指令完成受控部署，不重派實作。
- 部署後若異常，回滾已備份版本並開新 Issue，不自行 debug。工程只為誠實學習與資金成長，不為看起來複雜。
- Issues 批次回報一則短訊息（編號、標籤、一句摘要）。建立 Issue 只代表已排隊，不能假稱外部 agent 已開始。
- 本節取代先前要求助手親自測試、review、debug 或立即自行修碼的工程流程。帳戶、窗口、歷史及實盤權限邊界不變。

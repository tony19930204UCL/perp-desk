狀態：規格已建立，C-0112 等 C-0093 看板路由修正。沒有宣稱已派送 ChatGPT。

使用者授權：ChatGPT 負責設計與實作，程式與網頁資產交付 GitHub 非 main 分支及 PR。Perp Desk 經營者驗功能、真實帳務與部署，使用者驗視覺。不碰其他 profile 或實盤。

目前實看：既有 dashboard.html 是研究／觀察員 console，總覽顯示未設定研究，歷史帳戶頁才能看到單臂 W1 ETH 資金。這不是完整 12 臂交易台。現存 /api/status 為單臂資料。不要把其他 profile 8765/8766/8875 的服務當成本專案。

## 最新授權與委派方式（使用者修訂）
ChatGPT 全權負責範圍內的產品調查、資訊架構、互動、視覺與程式實作。我們交付系統背景、觀察者任務、真實資料邊界及驗收契約，不交一份逐像素施工圖。下方欄位是需求，不是固定版型。ChatGPT 自己決定頁面、排序、欄位安排、密度、圖表與技術分工，必須記錄重大取捨。

## 可直接納入工程指令的自主設計任務
你是這項交付的產品設計與前端負責人，不是照稿切版的人。系統是24小時執行的加密永續合約紙盤研究台，多個獨立臂、各自帳務與前瞻窗口。觀察者要快速知道：現在有哪些部位、賺賠多少、已平倉交易如何賺賠、資料是否即時、系統或工程哪裡有問題。你不能替交易員改策略、風控、交易行為或歷史。

BACKGROUND：既有 console 以研究與工程資訊為主，沒有完整交易台體驗。使用者希望學習 Binance Futures 的資訊密度、可掃讀性、持倉及歷史交易操作邏輯，不是複製標誌或冒充 Binance。你的任務是設計適合我們系統的原創交易觀察介面。

TASK：先調查再設計，然後實作。不要反覆問觀察者要怎麼排欄位，低風險設計決策由你自己做。
1. 讀實際 repo 的說明、runtime、broker、API、snapshot 契約、測試與現有前端。列出真實功能與資料來源對照，每個重要欄位註明『已存在／可唯讀推導／缺少且不能虛構』。沒有 repo 或來源讀取證據，不能宣稱已理解系統。
2. 用可用瀏覽器或網路工具研究 Binance 官方公開的合約介面、說明或官方截圖。保存實際看過的來源與觀察，分清現行產品與歷史示意。若登入／地區限制擋住，使用官方公開說明並直說限制，不能憑記憶聲稱實看。提出哪些原則值得借用、哪些功能不適合我們。
3. 自己整理觀察者的核心使用情境與資訊優先級，至少提出兩種有實質差異的版面方向，自己選一個最符合本系統的，說明取捨。這是 Monitor／Inspect 介面，不是行銷落地頁，不做 hero 或裝飾性的假績效卡。
4. 決定 UI、互動、欄位、響應式行為、空資料／錯誤／過期狀態。保留選中臂與頁籤，數值刷新不破壞使用者正在讀的列。補上你調查後認為必要但我們沒提到的唯讀體驗，只要有真實來源且不擴張交易權限。
5. 完成可操作網頁，不只產出企劃或靜態 mockup。逐階段保存到既定 GitHub 分支，交付設計理由與可執行版本。若僅缺某欄資料，該欄清楚顯示不支援，不用假值補滿。遇到需要新檔案或來源超出 write_allowlist，具體回報所需範圍，不自行擴張。

TESTS／ACCEPTANCE：依下方功能真實性與安全條件做測試，實際啟動網頁、點擊主要路徑並檢查 browser console，桌機與手機 viewport 各截圖。自行檢查是否有過多裝飾、資訊沒有層級、表格不可讀或手機溢出，修正後再交付。截圖中的模擬測試資料必須明示 fixture，不能冒充實際帳戶。助手驗功能與對帳，使用者驗視覺，不需使用者先替你選版型。

交接要求：repo、PR／Issue、完整 head SHA、CI run／結果、啟動入口、實際測試與截圖、未部署狀態、已知限制及範圍外改動。無法執行的測試寫 NOT_RUN，禁止編造。正式派工另附固定的 repo／branch／mailbox／write_allowlist 與 schema-v2 MAILBOX FORMAT，不由你猜。

## 視覺方向（參考，不是固定版型）
Binance Futures inspired，非冒充官方。繁體中文、交易資料可掃讀、盈虧清楚、桌機密度與手機可讀性。ChatGPT 自行決定色彩、版面與元件，不強制右側摘要或固定頁籤位置。PAPER 與唯讀常駐醒目標記。不以空白研究 console 冒充交易台，不為裝飾造行情或績效。

## 資訊架構
1. 帳戶摘要：本金、現金、權益、已實現／未實現／總損益、費用、已結算資金費率、時效與窗口狀態。
2. Positions：臂、標的、方向、數量、進場均價、mark、名目曝險、未實現損益、風控與出場條件（來源支持才顯示）。
3. Closed Positions：以實際 fills 重建 flat-to-flat episode，包含進出時間、方向、加權成交價、數量、毛利、費用、資金費率、淨利、持有時間與出場原因。部分平倉不能冒充完整來回。拒單不算成交。
4. Open Orders、Order History、Trade History 分頁。分清委託與成交。
5. 權益曲線保留完整歷史，不重設帳戶，不拼接作廢窗口。舊作廢窗口可明示歷史檢視，不計為新窗口。
6. 明確 allowlist 的12臂可切換，帳本各自隔離。若有組合摘要，只合計同一時間口徑，不把它說成一個真實券商帳戶。

## 真實性與安全
没有保證金／強平模型的臂：顯示未建模，禁止造可用保證金、強平價、ROE 或逐倉／全倉狀態。缺／舊資料清楚顯示，不以零值取代缺失。金融值後端 Decimal 字串，前端只做顯示 rounding。無下單、撤單或平倉按鈕，無寫入 API，只綁 loopback。機密或本機私人路徑不得出現在公開 GitHub。

## 驗收分工
ChatGPT：交付 HTML/CSS/JS 與必要唯讀資料接線、可執行入口、tests、精確 head SHA、CI run/結果、桌機手機截圖、未部署與範圍外變動說明。分小單元派工，第一單元先證明12臂資料與已平倉帳務來源，再做介面。
助手：精確 head CI、乾淨副本測試、各臂 API 與原 snapshot/ledger/fills 對帳、缺失與 stale、部分成交、费用／funding、唯讀防護、Windows/WSL 同埠 HTTP 與真 browser refresh。
使用者：視覺驗收，可要求密度、顏色、頁籤、欄位和手機版調整。功能通過不等於使用者視覺已通過。
